# P6：Production Readiness

**状态：未开始（仅阶段级规划，暂不拆任务）**

---

## 一、阶段目标

把 MVP Agent 变成**稳定、可恢复、可观察、可评测、可分发**的系统。

P6 是能力面最宽的一阶段，建议在展开为任务时拆成若干子阶段（如 6A 可靠性、6B 记忆与检索、6C 多 Agent 与 Workflow、6D 可观测与评测、6E 安全与发布），每个子阶段独立验收。

---

## 二、主要能力

### 可靠性
- **Checkpoint**：Run 在关键步骤（每轮模型调用后、每次工具执行后）落检查点。
- **Resume**：中断（进程崩溃、取消、重启）后从最近检查点恢复执行。
- **Run Persistence**：Run 的完整状态机与步骤历史持久化，可重放。
- **Task Recovery**：长任务的分段执行与失败重试；不可重试失败给出明确终态与原因。

### 记忆与检索
- **Memory**：跨 Session 的长期记忆（事实、偏好、约定），带来源与时效。
- **Context Compression**：长对话的摘要与压缩（保留决策与结论，丢弃过程噪声）。
- **RAG**：文档导入、分块、检索、引用回填。
- **Vector Search**：向量存储与检索（初期可用 SQLite 扩展或独立嵌入式索引）。

### 协作与编排
- **Multi-Agent**：子 Agent 派生、任务委派、结果汇总、预算隔离。
- **Workflow**：把多步骤任务表达为可恢复的流程（顺序、分支、并行、等待人工介入）。

### 可观测与评测
- **OpenTelemetry**：trace / span 覆盖 Run、模型调用、工具调用、MCP 调用。
- **Metrics**：延迟、token 用量、成功率、工具错误率、队列深度。
- **Evaluation**：可重复的评测集与评分（任务成功率、步骤效率、工具选择正确率）。

### 安全与分发
- **Security**：密钥管理、工具权限的持久化审计、敏感信息脱敏。
- **Sandbox**：工具执行的隔离（进程级 / 容器级 / WASM），资源限制（CPU、内存、时间、文件系统）。
- **Resource Isolation**：单 Run 的资源配额，防止单任务拖垮进程。
- **Release**：版本号策略、变更日志、升级与配置迁移。
- **Cross Platform Distribution**：Windows / Linux / macOS 构建与分发（安装包、自动更新、开机自启能力）。

---

## 三、核心技术

- **OpenTelemetry**（Rust SDK）+ 现有 logging 体系融合。
- **SQLite**：检查点、记忆、评测记录；必要时引入向量扩展或嵌入式索引。
- **Tokio**：任务编排、超时与配额、优雅降级。
- **沙箱**：平台相关（Windows Job Object / Linux cgroups+seccomp / 容器），需分平台实现。
- **CI/CD**：多平台构建矩阵、产物签名、版本与迁移脚本。
- 框架已有的 `framework-startup`（Windows 任务计划 / systemd / launchd 自启动）可用于分发阶段的开机自启。

## 五、主要交付物

1. 检查点与恢复机制（含状态机持久化与重放）。
2. 记忆子系统与上下文压缩。
3. RAG 与向量检索能力（含文档导入流程）。
4. 多 Agent 委派与 Workflow 执行引擎。
5. OpenTelemetry 接入与关键指标面板。
6. 评测框架与基线评测集。
7. 沙箱与资源隔离实现。
8. 发布流程：版本策略、迁移、跨平台产物、分发渠道。

## 六、阶段验收方向

1. 杀死进程后重启，进行中的 Run 能从最近检查点恢复并完成。
2. 长对话（超出上下文窗口）经压缩后仍能保持任务连续性（用固定用例验证）。
3. 记忆能跨 Session 生效，且可查看来源、可删除。
4. RAG 检索结果带引用，回答可追溯到原文片段。
5. 一次复杂任务可分解给多个子 Agent 执行并正确汇总，总预算不超限。
6. 全链路可在 OTel 中看到 Run → 模型 → 工具 → MCP 的完整 trace。
7. 评测集可一键运行并输出可对比的分数（同一版本重复运行结果稳定）。
8. 恶意或失控的工具调用被沙箱约束（越权文件访问、超时、内存超限均被拦截）。
9. Windows / Linux 至少双平台产物可用，安装与升级路径明确。

---

## 七、Non-goals（本阶段明确不做）

- 微服务化拆分、分布式调度、多机集群。
- 多租户 SaaS 形态与计费体系。
- 面向第三方的插件市场与开放平台。
- 自研向量数据库内核（只在嵌入式方案不足时再评估）。

---

## 八、风险与待讨论问题

1. **阶段过大**：P6 内容量远超 P1–P5，必须拆子阶段并分别验收，否则会变成“永远做不完的阶段”。
2. **恢复语义的正确性**：Checkpoint 粒度越细成本越高；工具执行的副作用（如已发出的 HTTP 请求）不可回滚，恢复时如何避免重复副作用（幂等键？只允许恢复到“无副作用边界”）。
3. **压缩与记忆的质量**：压缩可能丢失关键约束，需要评测支撑而不是凭感觉。
4. **沙箱的跨平台成本**：Windows 与 Linux 的隔离机制差异极大，可能只能做到“分级安全”（不同平台不同保证）。
5. **向量检索选型**：嵌入式向量索引（如 SQLite 扩展）与外部服务的取舍，直接影响“单 Binary 分发”承诺。
6. **评测集的代表性**：评测集若只覆盖简单任务，会给出虚假的安全感。
7. **可观测性开销**：全量 span 带来的性能与体积成本，需要采样策略。
8. **发布与迁移**：配置与 SQLite schema 的向前兼容策略，用户升级失败如何回滚。
