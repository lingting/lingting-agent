## 四、注意点

1. **分批墙钟不可跨批相加做全量推断**：每批都重建一次共享服务端、重新 `gen`，八批合计 55s 高于全量一次的 34s，属分批的成本，不是回归。
2. **`web` 与 `tui` 是两条长尾**：`web.ui` 单次 6.8~9.9s（Playwright）、`tui.reconnect` 15.1s（`RECONNECT_TIMEOUT = 25s` 内的设计耗时），批内并行度低，这两批的墙钟主要由它们决定。
3. **`runtime.rotation` 快得反常（421ms）是因为它只操作注册表与文件，不起 Run**：与事件落盘路径的对照见 P2.1-013 的指标快照。
