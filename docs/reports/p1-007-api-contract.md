## 2. 生成入口：根 `Makefile`

`scripts/build.sh` / `check.sh` / `gen.sh` 已删除，仓库根 `Makefile` 成为唯一命令入口：

| 目标 | 行为 |
|---|---|
| `make gen` | `cargo run --quiet -p lib-web --example gen_sdk`（同进程依次生成 Rust 与 TS） |
| `make build` | `cargo build $(ARGS)` |
| `make check` | `cargo fmt --all --check` + `cargo clippy --workspace --all-targets -- -D warnings` |
| `make fmt` | `cargo fmt --all` |
| `make clean-gen` | 删除 `packages/` |
| `make ui-install` / `ui-dev` / `ui-build` / `ui-lint` | 在 `lingting-agent-ui/` 内执行对应 pnpm 脚本 |

取舍说明：

1. **一条命令产出两份 SDK**：`make gen` 只调一次 example，两个生成器同进程串行执行，任一失败即中止并非 0 退出，不需要额外脚本判断退出码。
2. **帮助文本外置到 `.make/help.txt`**：Windows 版 GNU Make 按 ANSI 代码页解析 Makefile，UTF-8 中文写在 recipe 里会变成乱码（实测），因此 `help` 目标改为 `cat` 一个 UTF-8 文本文件。
3. **recipe 依赖 POSIX sh**：`make` 需在 Git Bash 中执行（`clean-gen` 使用 `rm -rf`），与项目既有终端约定一致。

## 3. 生成物落位与不入库

| 生成物 | 落位 | 消费方式 |
|---|---|---|
| Rust SDK | `packages/sdk-rust/src/{types,enums,api}.rs` | `lib-bin-cli` 用 `#[path]` 作为自身模块引入；不生成 `Cargo.toml` |
| TS SDK | `packages/sdk-ts/`（`package.json` + `dist/*`） | `lingting-agent-ui/` 的 pnpm workspace 以 `@lingting/agent-api: workspace:*` 引入 |

- `.gitignore` 的 `packages/` 规则已覆盖两份生成物与暂存目录。
- 因此“改 API 的完整步骤”中**没有提交生成物环节**：`tasks.md` 原验收项“改定义 → 跑生成 → 提交生成物”已修正为“改定义 → 跑生成 → `make check` / `make build`”。
- 头部标记：Rust 生成物首行写 `// 本文件由 make gen 自动生成，请勿手动修改。`；TS 生成物由框架写入 `This file has been generated by Specta. Do not edit this file manually.`（语义等价，未额外注入中文标记）。

## 4. 失败行为：暂存目录 + 按内容提交

两个生成器的写盘顺序统一为：

1. 收集元数据；元数据为空直接返回错误（不写盘）。
2. 全部 builder 构建成功（TS 侧 `PackageBuilder::write` 内部也是先 build 全部模块再落盘）。
3. 写入目标目录的同级暂存目录（如 `packages/sdk-rust/.src.gen-tmp`）。
4. Rust 侧在暂存目录内跑 `rustfmt`。
5. 按内容提交：暂存目录与目标目录逐字节比对，完全一致时只删暂存目录、不动目标目录（不刷新 mtime，避免 cargo 的 `#[path]` 依赖与前端依赖图无谓重编译）；有任一差异才整体替换——旧目录先 rename 到 `.src.gen-old`，暂存目录 rename 到目标位；rename 失败则把旧目录放回原位，成功后删除备份。

实现位于 `crates/lib-web/examples/support/sdk_out.rs`（`prepare_staging` / `commit`），两个生成器共用；生成器逻辑在 `examples/support/gen_{rust,ts}_sdk.rs`，由 `examples/gen_sdk.rs` 一次进程内顺序调用。

实测：

- 预置残留 `packages/sdk-rust/.src.gen-tmp` 后执行 `make gen`，残留被清理、生成成功。
- 连续执行两次 `make gen`，产物内容一致（幂等），暂存与备份目录不残留。
- 失败路径（元数据非法、rename 失败）本次未构造反例，靠上面的顺序与回滚逻辑保证：元数据错误发生在写盘之前；rename 失败会回滚。

## 5. 命名规范与版本策略

完整表格见 `docs/develop.md`「API 契约规范」，要点：

- path 前缀 `api/`，不带版本段；资源段小写单数名词、多词用 `-`；动作动词固定为 `create` / `update` / `delete` / `get` / `list` / `cancel`。
- 请求体 `*PO`、查询参数 `*Params`、响应 `*VO`、枚举 `<业务名>Kind`。
- 字段 camelCase；id 用 `String`；`i64` 在 wire 上以字符串传输（D-018）；查询参数不出现 `bool`（D-021）。
- 版本：P1 不版本化，`api/...` 直接演进；将来需要多版本并存时改用 path 前缀（`api/v2/...`），不采用请求头（D-019）。
