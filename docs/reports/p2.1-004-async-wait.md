# P2.1-004 消除测试进程同步阻塞（H-1）

- **阶段**：P2.1（Batch B）
- **任务**：P2.1-004
- **前置**：[`p2.1-002-blocking-audit.md`](p2.1-002-blocking-audit.md)（阻塞点清单与基线：27 次等待 / 4710ms，10 次收尾 / 42ms）
- **结论**：S-1a / S-1b / S-1c 三处同步阻塞全部消除。默认并发下**同步阻塞从 4752ms 降到 0ms**，同一批等待改成异步睡眠后不占 worker；用例名与断言零变更。

---

## 一、改动

| 位置 | 改动 |
|---|---|
| `lib-bin-tui/src/testing.rs` | 新增 `Harness::wait_until_async`（`pump()` + `tokio::time::sleep`）；新增 `Harness::close`（`spawn_blocking` 里 join 工作线程，收尾不再占 async worker）；同步 `wait_until` 保留给非 `async` 场景并在文档注释里写死「禁止在 `async` 上下文调用」 |
| `lib-bin-tui/src/testing.rs` | `BlockingSnapshot` 拆成同步 / 异步两套计数（`wait_* / shutdown_*` 与 `async_wait_* / async_shutdown_*`），`total_millis` 只统计真正占住 worker 的部分 |
| `bin-tests/src/cases/tui.rs` | `open()` 改 `async`，等待走 `wait_until_async` |
| `bin-tests/src/cases/tui/*.rs` | 18 处 `wait_until` → `wait_until_async`；10 条起过工作线程的用例在末尾显式 `harness.close().await`；`keys.rs` 的 `drop(harness)` → `harness.close().await`（同一条收尾路径） |
| `bin-tests/src/cases/rotation.rs` | S-1c：`create_sessions` 的 `std::thread::sleep(10ms)` → `tokio::time::sleep` |
| `bin-tests/src/observability.rs` | 「观测数据」里的 TUI 一节改成同步 / 异步两段，便于前后对照 |

`cases/` 内已无 `Harness::wait_until` 调用，也无 `std::thread::sleep`（`crate::support::wait_until` 本来就是异步的）。

## 二、修复前后对照（默认并发 18，73 个用例）

| 项 | 修复前（P2.1-002） | 修复后（第 1 次） | 修复后（第 2 次） |
|---|---|---|---|
| 同步轮询等待 | 27 次 / 4710ms | **0 次 / 0ms** | **0 次 / 0ms** |
| 同步收尾等待 | 10 次 / 42ms | **0 次 / 0ms** | **0 次 / 0ms** |
| 同步合计（占住 worker） | 4752ms | **0ms** | **0ms** |
| 异步轮询等待（不占 worker） | — | 27 次 / 4993ms | 27 次 / 4865ms |
| 异步收尾等待（阻塞线程池） | — | 10 次 / 160ms | 10 次 / 57ms |
| 墙钟 | 34.0s / 34.1s / 36s | 35s | 33s |
| 结果 | 73/73 | 73/73 | 73/73 |

读法：

- 等待次数与耗时量级（27 次、约 4.9s）与基线一致，说明**观测点没漏**，变的是「等待时占不占 worker」：同样的 4.9s 现在记在异步行。
- 收尾从 `Drop` 里的 `join` 改成 `spawn_blocking` 里 join：10 次 / 57~160ms 的墙钟不变，但不再压在 worker 上。
- 墙钟没有变快（35s / 33s vs 34s），符合预期：H-1 本来就不是本机默认并发下的失败原因（P2.1-002 已量化到人均 0.26s）。本任务的收益是**结构性的**——服务端变慢时 `wait_until` 不会再顺着同步 sleep 占住 worker 直到超时。

## 三、注意点

1. **S-1b 的处理方式**：`Drop` 无法异步，所以新增 `Harness::close`，由用例在末尾显式调用；没调用的路径仍走 `Drop` 的同步 join（离线用例没有工作线程，等于空操作）。
2. **同步入口仍在**：`wait_until` 保留给非 `async` 场景，仅文档注释约束，没有运行时防护。
3. **可观测性口径变更**：报告里「同步合计」才是 worker 占用；异步两行只作对照，不能相加。
