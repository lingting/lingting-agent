1. **G-1（结构性并发缺陷修复）成立**：四处缺陷各有「修复前 / 修复后」指标对照，默认并发下 `--all` 连续多轮全绿；K-1 的结论是**未复现 + 环境因素未排除**，全绿只作回归判据，不作为修复收益的证据（D-P2.1-007）。

3. **G-3（并发配置可表达核数倍数）成立**：`[agent] max_concurrent_runs` 支持 `"2C"` 写法，缺省 `"3C"`，整数写法保持兼容；显式 `4` 与默认 `3C` 两轮默认并发全量**均为 73/73**。
4. 全阶段未新增测试侧限流、未改 25 条接口与 `RunEvent` 契约、未改 Mock 契约、未为排查引入新依赖（`arc-swap` 已在 workspace，未向任何新 Crate 引入）。

## 四、G-3 并发配置增强（P2.1-015）

### 4.1 实现要点

| 项 | 内容 |
|---|---|
| 值类型 | `types-core::config::agent::Concurrency`：`Absolute(usize)` / `Cores(usize)`，`Default = Cores(3)`，`DEFAULT_MAX_CONCURRENT_RUNS` 同步改为该类型（默认值只有一处） |
| 解析 | 自定义 `Deserialize` 走 `deserialize_any`：整数（含旧写法 `4`）→ `Absolute`，`"NC"`（`C` / `c` 后缀）→ `Cores`；错误文案在解析阶段就点名字段 |
| 校验 | `lib-bin-cli::config::validate_max_concurrent_runs`：`0` / `0C` → 「必须大于 0」，`2X` / 非数字 → 「取值无效」，负数 → 「不接受负数」，超过 `Concurrency::MAX_PERMITS` → 「超过可用上限」 |
| 装配 | `agent-runtime::AgentRuntime::new`：`available_parallelism()` 只取一次，`resolve(cores)` 交给 `Semaphore::new`，运行期不变 |
| 上限保护 | `resolve` 为纯函数，结果落在 `1..=MAX_PERMITS`（与 `tokio::sync::Semaphore::MAX_PERMITS` 同值），倍数溢出按上限饱和，不 panic |
| 决策记录 | [`../.steps/p2.1/decisions.md`](../../.steps/p2.1/decisions.md) D-P2.1-015 |

`resolve` 的断言（`llm.config`，注入 8 核，不依赖真实机器）：缺省 `3C` → 24，`"2C"` → 16，整数 `4` → 4。

### 4.2 非法取值的文案（`llm.config` 的 5 类断言）

| 配置 | 错误文案（片段） |
|---|---|
| `max_concurrent_runs = 0` | `[agent] max_concurrent_runs 必须大于 0` |
| `max_concurrent_runs = "0C"` | `[agent] max_concurrent_runs 必须大于 0` |
| `max_concurrent_runs = "2X"` | `[agent] max_concurrent_runs 取值无效：2X（支持整数与 "NC" 形式，如 "2C"）` |
| `max_concurrent_runs = -1` | `[agent] max_concurrent_runs 不接受负数：-1` |
| `max_concurrent_runs = 9223372036854775807` | `[agent] max_concurrent_runs 超过可用上限 2305843009213693951（9223372036854775807）` |

## 五、根因假设的验证结论

| 假设 | 结论 | 依据 |
|---|---|---|
| H-1 `async` 上下文里的同步等待阻塞 worker | **成立（已修）** | 27 次同步轮询 / 4710ms + 10 次同步收尾 / 42ms 全部改为异步；修复后同步两行为 0 |

| 表级内存快照可消除读放大 | **不成立（不改，口径留档）** | 执行期 10 类访问全部落在 API 请求上，整轮全量「取数据库连接」仅 3 次；无高频 + 可陈旧 + 非权威的读路径（D-P2.1-012） |

## 七、下游（P3）输入清单

1. **并发配置面**：`[agent] max_concurrent_runs` 支持 `"NC"` 与整数；新增并发相关配置请沿用「值类型 + 纯函数 `resolve` + 装载层校验」的形态（D-P2.1-015）。
2. **观测入口**：进程内指标只在 `metrics` 特性下采集（D-P2.1-008），测试报告的「观测数据」一节是既有读取口；P3 的工具执行链路若要观测，沿用同一开关，不要常驻编译。
3. **锁使用原则**：纯内存短读写用 `std::sync`、跨 `await` 的互斥用 `tokio::sync` 且不把收尾 / 重试放进临界区、读多写少先「取快照后放锁」（README §5.3、D-P2.1-010）。
4. **测试结构**：`bin-tests` 只允许 `cases` / `mock` / `util` 三层（`cases → {util, mock}`），领域自有的探测不要跨领域复用（D-P2.1-013）。
5. **待观察项**：`session/list` 与 `message/list` 的读放大、共享服务端 100ms 级排队分布、默认 `3C` 在真实 Provider 下的上游配额。
